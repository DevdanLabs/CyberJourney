# FlareVM: Arsenal of Tools

## Executive Summary

Malware analysis is a fundamental discipline in modern cybersecurity, enabling analysts to understand how malicious software operates, identify indicators of compromise (IOCs), and develop effective detection and response strategies. Before executing a suspicious file, security professionals typically perform **static analysis** to gather information safely, followed by **dynamic analysis** to observe the malware's behavior inside an isolated environment.

In this TryHackMe room, we explored **FlareVM (Forensics, Logic Analysis, and Reverse Engineering Virtual Machine)**, a Windows-based virtual machine specifically built for malware analysis, reverse engineering, digital forensics, and incident response. FlareVM provides a comprehensive collection of industry-standard security tools, allowing analysts to investigate suspicious files without spending hours configuring individual applications.

Throughout this room, I became familiar with the overall structure of FlareVM and learned how different tools contribute to the malware investigation workflow. I performed static analysis using tools such as **PEStudio**, **CFF Explorer**, and **FLOSS**, then continued with dynamic analysis using **Process Explorer** and **Process Monitor** to observe process creation, imported APIs, parent-child relationships, and network activity. Finally, I collected Indicators of Compromise (IOCs), including cryptographic hashes, imported functions, process information, and network connections.

Rather than focusing on reverse engineering the malware's code, this room emphasizes developing a structured investigation methodology—an essential skill for SOC Analysts, Incident Responders, Digital Forensics Analysts, and Malware Analysts.

# Terminology

| Term | Description |
|------|-------------|
| **FlareVM** | A Windows virtual machine containing numerous malware analysis, reverse engineering, and forensic tools. |

| **Entropy** | A measurement indicating how random or compressed a file's contents appear. High entropy often suggests packing or encryption. |

| **Child Process** | A process created by another process. |
| **Imphash** | A hash calculated from the Import Address Table, commonly used for malware family identification. |

# Understanding FlareVM

## What is FlareVM?

**FlareVM (Forensics, Logic Analysis, and Reverse Engineering Virtual Machine)** is a Windows-based security virtual machine developed by the **FLARE Team** (formerly FireEye, now Trellix). It is specifically designed for malware analysis, reverse engineering, digital forensics, and incident response.

Unlike a standard Windows installation, FlareVM comes preloaded with hundreds of specialized tools that security professionals use daily. Instead of spending hours installing and configuring software individually, analysts can immediately begin investigating suspicious files within a safe and isolated environment.

FlareVM can be thought of as the Windows equivalent of **Kali Linux**, but instead of focusing on offensive security and penetration testing, it focuses on malware investigation and defensive analysis.

---

## Why Do We Need FlareVM?

Imagine receiving the following email attachment:

```text
Invoice.pdf.exe
```

At first glance, it appears to be a PDF document.

However, it is actually an executable disguised as a document.

Running this file directly on a production workstation could result in:

- Credential theft
- Data encryption (ransomware)
- Backdoor installation
- Persistence mechanisms
- Command-and-Control (C2) communication
- Lateral movement

Instead of executing the sample on a normal computer, analysts use FlareVM to safely examine the malware inside an isolated laboratory.

# Static Analysis vs Dynamic Analysis

Malware analysis generally consists of two complementary approaches.

## Static Analysis

Static analysis examines a file **without executing it**.

Instead of observing behavior, analysts inspect characteristics such as:

- File hashes
- Metadata
- Digital signatures
- Imported APIs
- Strings
- PE structure
- Compiler information
- Entropy

### Advantages

- Very safe
- Fast
- No malware execution
- Easy to automate

### Limitations

- Cannot observe runtime behavior
- Packed or obfuscated malware may hide important information
- Cannot reveal network communications or memory activity

---

## Dynamic Analysis

Dynamic analysis involves executing malware inside an isolated virtual machine while monitoring its behavior.

Analysts observe:

- Process creation
- Registry modifications
- File creation
- DLL loading
- Network communication
- Memory allocation
- Child processes

### Advantages

- Reveals actual malware behavior
- Identifies runtime indicators
- Detects persistence mechanisms
- Shows network activity

### Limitations

- Requires an isolated environment
- Malware may detect virtualization
- More time-consuming
- Higher operational risk

---

# Static vs Dynamic Analysis Comparison

| Static Analysis | Dynamic Analysis |
|----------------|------------------|
| Does not execute malware | Executes malware safely |
| Safer | Higher risk |
| Fast | Slower |
| Examines file structure | Examines runtime behavior |
| Identifies metadata | Identifies malicious actions |
| Suitable for initial triage | Suitable for behavioral analysis |

Professional investigations almost always begin with **static analysis** before moving to **dynamic analysis**.

# Why So Many Tools?

At first glance, FlareVM may seem overwhelming because it contains hundreds of applications.

However, this mirrors real-world environments.

Think of FlareVM as a mechanic's toolbox.

A mechanic doesn't use every tool simultaneously.

Instead, they choose the right tool depending on the problem.

The same principle applies to malware analysis.

For example:

- Need to inspect executable metadata?

- Need to observe process behavior?
  - Use **Process Explorer**

- Need to inspect network traffic?
  - Use **Wireshark**

- Need to reverse engineer malware?

Understanding **when** to use a tool is significantly more important than memorizing every available application.

# Process Monitor (Procmon)

## Overview

Process Monitor (Procmon) is one of Microsoft's **Sysinternals** tools designed to monitor Windows activity in real time.

It records nearly every interaction occurring within the operating system, including:

- File system activity
- Registry activity
- Process creation
- Thread creation
- DLL loading

Because of its detailed logging capabilities, Procmon is one of the most valuable tools for malware analysts and incident responders.

---

## Why It Matters

Many malware samples leave traces throughout the operating system.

Examples include:

- Creating files
- Deleting files
- Editing registry keys
- Launching child processes
- Accessing sensitive Windows components

Without Process Monitor, these activities would be difficult to observe.

# Blue Team Perspective

For Blue Team operations, this room reflects a common malware triage workflow.

Typical investigation process:

1. Receive an alert from an EDR, SIEM, or antivirus.
2. Perform static analysis without executing the file.
3. Collect Indicators of Compromise (IOCs).
4. Execute the sample in an isolated environment if necessary.
5. Observe process behavior.
6. Monitor network communication.
7. Correlate evidence from multiple tools.
8. Produce an investigation report.

This structured methodology minimizes risk while improving confidence in investigative findings.

# Common Mistakes

During malware analysis, several mistakes should be avoided.

## Running Malware on the Host Machine

Always use an isolated virtual machine.

Never execute suspicious binaries on a production system.

---

## Relying on a Single Tool

No individual application provides a complete picture.

Professional investigations correlate evidence from multiple independent sources.

---

## Assuming High Entropy Equals Malware

High entropy may indicate:

- Compression
- Encryption
- Packing

It should be treated as an indicator rather than definitive proof of maliciousness.

---

## Trusting File Names

Attackers frequently disguise executables as legitimate applications.

Always verify:

- File path
- Digital signature
- PE structure
- Metadata
- Hashes
